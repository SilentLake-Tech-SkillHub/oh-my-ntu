# 01 教师原始课件

在 `01_课程课件/` 保存教师原始 PDF/PPT、课堂视频、Tutorial 原件、配套代码及数据。读取 [通用默认合同](../../references/defaults.md)；用户指定的结构和命名优先。01 根目录不平铺文件，默认两级分类：

- **一级按课次**：`WeekN_<主题>/`，主题取该周讲义标题的中文概括，如 `Week3_第3章_深度学习/`、`Week1_数据剖析与清洗/`。课程按章节组织时，章节与周的对应必须来自官方日程、平台分组或用户确认；未确认前用 `ChapterN_<主题>/`，确认后再改名。跨周材料放 `00_` 开头的一级目录：`00_课程说明/`（大纲、时间表、Course Briefing）、`00_课程案例/`（多周共用的案例）。只建有内容的目录。
- **二级按用途类型**：每个 Week 内分 `讲义/`（Lecture PDF/PPT）、`视频/`（课堂录像附件）、`Notebook/`（教师演示代码、配套 Notebook 与数据）、`Tutorial/`（Tutorial 题目、Briefing、教师 Answers 及其配套代码、数据、PPT）。只建有内容的子目录；代码依赖同目录数据时，两者放同一子目录。
- **逐个文件判定后再归类**：每个文件都要打开核对，不能只抽查看起来有疑问的。核对标题、首页或首个 Markdown 单元，以及它在学生平台的栏目，按实际用途归类，不按文件名或扩展名猜。标题含 Tutorial／Exercise／Practice，或带题目和 `your answer here` 之类作答区的 Notebook，以及与之配套的教师 Solution／Answers，都归 `Tutorial/`；纯演示或讲义配套代码归 `Notebook/`。
- **课程代码不一致时先查平台**：文件内部写着其他课程代码时，先只读核对学生平台。如果它由本课教师发布在本课课程页，且内容对应本课的 Tutorial 或讲义，就按本课材料归类，并在资料清单注明内部标题；只有平台无法证实时，才标来源待核对并暂放 `Notebook/`。
- **缺失和变化都要写明**：归类后在课程资料清单写出“Week × 类型”对应表、章节与周对应的依据和待核对项。某周没有某类子目录时，表中写明“平台该周无此类附件”及核对日期，不能只是不建目录。平台可见性变化（如栏目变空、附件消失）照实记录；已按来源取得并核对过的原件保留，不写成“教师已删除”。
- **文件名**：默认 `WeekN_Weekday_主题.扩展名`，但上课日必须有证据；证据不足时保留教师原文件名，不猜。配套代码依赖固定文件名时保留运行所需的名字。
- **整理已平铺的目录**：按默认合同先备份、记录哈希，再移动；逐条重算所有引用，包括 Notebook 元数据中的来源路径；完成后核对链接为 0 断链、01 文件哈希集合不变。

先取得教师课程页或用户提供的原始清单，再逐项核对本地实体、格式、页数或大小、版本及来源。遇到文件内课程代码与所在目录不一致，先标来源待核对，不能只凭文件位置认定为本课程教师原件。不得把公告、考试分组、课堂字幕或 AI 笔记混作教师课件：公告及考试通知交由 06，派生笔记交由 03–05。原件不改写，不以快捷方式或符号链接替代。Tutorial 原件在 01 保存正本；03 的 Tutorial 合集另放逐字节相同的副本（见 [03 第 8 节](../【课件预习笔记】ntu-courseware-to-notebook/SKILL.md)）。01 原件更新时，同步替换 03 副本并复核哈希。来源缺项如实列出，不因部分 Week 已齐全宣称课程全覆盖。哈希可用于过程校验，但除非用户明确要求完整性清单，不在课程根目录留下独立 `SHA256SUMS*.txt` 作为成品。

访问已确认的学生平台前向用户说明 Computer Use 的只读目标与范围；登录由用户处理，不绕过访问控制或通过非官方分段流获取文件。完成后核验实体能打开、与清单对应；内容解析、翻译或复习另交相应子 SKILL。

## 下载与原生保存窗口

用户已要求取得附件时，完成下载触发、保存和本地读回这一整段操作。出现“另存为”窗口，读取当前文件名、目标目录和保存按钮状态；将目录设为本轮课程目标或临时下载目录，确认“前往文件夹”等子窗口已关闭、保存按钮已启用，再保存。不要把未处理的窗口留给用户，或在首份还待保存时堆叠新的下载。仅能确认存在保存窗口而不能操作时，说明具体阻塞及待保存文件。

已登录浏览器的 DOM 下载与 macOS 原生保存窗口是两个操作面；在 macOS 可用系统辅助功能读取和操作原生控件。键盘操作前确认目标应用与窗口，输入目录后等候自动补全并读回实际目录，避免把路径输入其他应用。不要更改用户全局下载偏好来替代一次保存；不得复制 Cookie 或浏览器个人资料。

保存后逐份确认实体路径、大小、真实格式与首个内容单元，再进行归类和需要的副本哈希核对。HTML 登录页、空文件、未完成下载都不算原件。平台显示名与实际附件名可能不同：从本次下载入口和打开后的内容建立对应，必要时用平台区分名归档，记录原下载名，避免覆盖不同练习；文件内容保持原样。重复或误存副本只有在确认本轮归属、逐字节相同且正本已保留后才归档，不按相似文件名删除。
