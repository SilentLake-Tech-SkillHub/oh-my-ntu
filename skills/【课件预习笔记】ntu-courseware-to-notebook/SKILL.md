# NTU 课件转预习 Notebook 标准

本文件是 [NTU 课程主 SKILL](../../SKILL.md) 的“【预习用】03_Notebook课件中英文对照解析”子 SKILL。现有课程代码仅是实例；其他课程须核对其真实来源和目录。本文件不自动安装或注册到 Codex 全局 Skill 库。

以下均为默认设置。用户可以在具体 Prompt 中修改目录、命名、内容、格式、语言或验收要求；当前任务的明确要求优先。

## 交付标准

每张纳入范围的英文原版幻灯片，紧跟一份完整、自然、可选择、可复制、可搜索、可编辑的中文 Markdown 翻译。阅读体验应与逐页在聊天中认真翻译时一致：标题清楚、要点连贯、层级合理、术语对照、表格可读。默认同时交付从最终 Notebook 生成的同周离线 HTML 阅读版，供快速查阅；HTML 不替代可编辑 Notebook。以用户当前要求为准；一次已确认的格式无需每周重新询问。

这份 Skill 管理课件笔记制作。题库、速记卡、课堂录音、作业和其他周文件，只有被用户纳入范围时才处理。

## 默认交付位置与文件边界

- 教师原始 PDF/PPT、Tutorial、配套代码和数据的正本留在课程的 `01_课程课件/`；预习 Notebook 放在 `【预习用】03_Notebook课件中英文对照解析/Week01/`、`Week02/` 等对应周目录。跨周合并须有用户明确要求或已有获确认成品，不因制作方便自行合并。
- 每个 Week 的 03 目录只保留最终 `.ipynb`、同周离线 `.html` 阅读版及两者离线打开、显示和运行实际必需的实体资源；原页图片被引用时必须随同交付。资源目录默认命名为 `【勿删】<课程>_<WeekXX>_<Notebook用途>_原页图片/`，`【勿删】` 放在开头，不用含义不清的 `_assets`。例如 `【勿删】CAXXXX_Week04_课件中英对照_原页图片/`。
- 图片链接使用 notebook 同一 Week 目录下的相对路径；移动或改名时同步修改并验证全部链接。不得以快捷方式或符号链接代替实体 notebook/图片；被引用的图片不可删除。过程 OCR、候选裁切和临时预览不留在最终 03 目录。
- 03 是课前预习，不混入周度复习 HTML 或题库。Tutorial 的原件副本、翻译、讲解与解答按第 8 节组织在 03 的 Tutorial 合集中，不放 04。

## 1. 确定来源、页数与目标

1. 定位实际课程目录，按需读取项目入口与局部规则；核对课程、周次、章节、PDF 完整路径及目标 `.ipynb`。IDE 的旧活动文件名不应覆盖用户新指定的文件名。
2. 只以英文原版课件和用户提供的原图为翻译依据。排除文件名中“中英对照”“翻译版”等派生文件；不要抽取其中文，也不要把翻译截图插入 notebook。
3. 用户说“这些上传的图片”时，按上传范围匹配原版幻灯片；说“整周／整份 PDF”时覆盖相应全部幻灯片。处理章节和页码重复、非连续页码、重复截图；记录选择和遗漏理由。不要把某次 Week4 的 41 页固化为所有周的标准。
4. 区分 **PDF 物理页**、**页内位置**、**幻灯片印刷页码**。一张 PDF 物理页可能放两张或更多幻灯片。用标题、印刷页码、图表共同确认对应关系，不只依靠文件顺序或公式猜测。
5. 记录源文件 SHA-256、选页／幻灯片范围和每张幻灯片的位置。映射样例见 [references/notebook-contract.md](references/notebook-contract.md)，首次组装 notebook 时读取。

## 2. 保护当前笔记

- 修改前检查文件是否存在、是否为空、能否解析，以及现有 cells、metadata、代码 outputs、附件和图片引用。记录现有文件哈希并保留可恢复备份，备份放临时工作目录。
- 核对编辑器是否有未保存内容。优先安全保存用户目标 notebook，再读取磁盘内容。出现编辑器与磁盘不同步时，先比较并合并；不要自动丢弃编辑器版本，也不要用旧缓存覆盖新版本。
- 用户原有单元、批注和输出原样保留，默认在其后追加。生成内容需要稳定来源标识，便于重新运行时定位到对应页。
- 写入前再次核对目标哈希；若文件被用户或另一会话改动，重新读取并保留新内容。不要按 metadata 标签批量删除用户已编辑过的生成单元。
- 课程原 PDF 保持原样；资产使用 notebook 相对路径。只更新明确属于本次目标的 notebook、图片及其必要辅助文件。

## 3. 从英文原版提取清晰图片

- 用 `pdfinfo` 或等效工具检查页数、尺寸与旋转，用 `pdftotext -layout` 辅助读取英文。文本提取不能代替查看原始页面。
- 来源为 PPT/PPTX 时核对原始幻灯片数量、顺序、可见图层与备注；导出图片后与原文件逐页比对。不要把 PDF 专用的物理页／裁切坐标规则机械套用到 PPT。
- 先渲染代表页，确认一页一张／上下两张／多页拼版和裁切边界，再批量提取。遇到版式变化逐页调整。
- 优先从原 PDF 渲染 PNG，通常约 200–240 DPI 起步；以正文、图内小字、代码能清晰阅读为准。裁切保留整张幻灯片、标题、页码、图例和引用，不截断内容，不额外重绘原图。
- 现有上传图无法直接保存时，可从本地原版 PDF 获取对应幻灯片。若找不到相应原版，明确缺失来源；不得用相似内容替代。
- OCR 仅用于原文无法正常提取时的辅助转录。必须对照图像修正阅读顺序、连字符、数字、符号和代码缩进。
- 裁切参数基于当前 PDF 实测。历史 A4 两页拼版的固定坐标和奇偶页公式不能不经验证直接复用。

## 4. 逐页翻译与覆盖核对

按整张幻灯片阅读后翻译，确保以下内容在中文文本中得到覆盖：

- 主标题、副标题、每个正文要点与下级要点。
- 例子、括号解释、条件、限制、数字、比例、年份与否定关系。
- 表头和所有行列、坐标轴、图例、象限、箭头关系、图中标注及对话气泡。
- 页脚有实际参考意义的来源与图像署名；作者、书名、网址保留可核对形式。机构徽标及重复页码可由原图和单元标题承载。

译文要求：

- 逐项完整翻译，不能压缩为几句摘要，也不能添加原页没有的对比表或观点并冒充原文。
- 使用自然中文，把 PDF 自动换行重组为完整语义句。不要输出孤立的 `•`、断裂短语、逐行 OCR 痕迹或一大段无层级文本。
- 关键术语在所在页首次出现时保留英文，如“能力增强（Augmentation）”“自动化（Automation）”。原文不清楚时结合当前页解释，确实不可辨认则标注待核对，禁止编造。
- 区分译文与补充讲解。用户只要求翻译时不扩写大段教程；确需解释缩写或原文笔误，使用单独“译注”说明。
- 对原课件中的文化概括、过时论断和有争议的事实，忠实译为课件观点；不要无标记地改写为最新事实，也不要擅自替换原文。
- 已有聊天单页译文可以复用，但必须逐项回对英文原页，补齐漏译内容。历史生成脚本和“已完成”描述不能代替内容审校。

**图示重点**：用户旅程中的 Persona / Actor、Scenario、Expectations、Journey Phases、Actions、Mindsets、Emotions、Opportunities 及各阶段内部文字均需译出。复杂布局可用中文表格或分区列表重建关系，不能只翻正文而漏图内标签。

**代码重点**：代码、变量名、API 名、符号、缩进、输出、公式与示例数据保持原文。中文解释放在代码外；不要为了“修正”示例改变原课件语义。若确有错误，保留原代码并单列译注／修正版。按原稿保留注释，必要时在代码外翻译注释。只有用户要求可运行代码时才增设 code cell；仅制作笔记不运行整本代码。用户另要求逐行讲解时，再解释参数、返回值、作用域和运行过程。

## 5. 组装为可编辑 Notebook

- 默认采用相邻两个 Markdown 单元：先“章节／页码 + 英文原图”，后“中文标题 + 完整中文翻译”。已有 notebook 使用一个单元容纳一组时，可延续，只要图和译文紧邻且逐页对应。
- 普通 Markdown 内容必须存入 `cell.source`，不能将翻译放进图片、代码输出或整段 HTML 截图中。
- 标题、段落、列表前保留适当空行；使用 `- ` 或编号形成真实列表；子项正确缩进；同一语义句不沿用 PDF 硬换行。
- 表格使用 Markdown 表头和分隔行，处理单元格中的 `|`；代码使用带语言标识的 fenced code block 并保留缩进。图中文字映射表应忠于原图。
- 相同术语用法一致；按原页顺序组织。目录适合多章节、长 notebook 时再添加，原有目录可复用。
- 将原图放到与 notebook 相邻、以上述 `【勿删】` 前缀命名的实体资源目录，用包含章节与来源定位的唯一文件名，避免不同 PDF 的 Slide 3 相互覆盖。
- 组装脚本只负责渲染、映射、写入和结构检查；翻译内容由逐页阅读产生。不要调用旧译文 PDF 抽取流程冒充人工翻译。
- 保存有效的 nbformat 4 文件，保留已有 metadata 和 cell ID。新增单元带稳定来源标识；重复运行不重复追加，同一源页存在用户修改时保留并合并。

## 6. 验证内容与真实显示

**文件与覆盖**：解析最终磁盘 notebook；核对纳入范围的每张幻灯片都有且只有一组原图与译文；相对图片引用全部存在且可读、没有指向快捷方式或符号链接；检查重复／缺页、源文件身份、原有单元保留情况。清点以“配对数”为主，不把单元数量当作翻译完整性证据。

**语义审校**：逐页对照英文原文核对译文覆盖与对应关系，尤其是图内小字、表格、数字、否定、示例和代码。扫描乱码、空项目、原始圆点、残余硬换行仅是辅助检查；扫描通过不能证明译文完整或准确。

**实际渲染**：在 VS Code / Jupyter 中打开最终 `.ipynb`，检查至少一页普通列表、一页复杂图表以及每种代码／公式版式；另检查各章节边界与最后一页。核对中文是真实文字、图片清晰、表格没有错列、粗体和列表正常、代码没有缩进丢失。发现某类缺陷后检查同类全部页。

- 给用户展示实际 notebook 的代表性截图，截图仅作验证证据，不取代译文。
- 通过 `nbconvert` 导出可辅助检查；自定义 HTML 预览有自己的 CSS 和 Markdown 解析规则，不能据此宣称 VS Code / Jupyter 渲染通过。
- 如果用户正在编辑且 UI 操作被打断，不反复抢焦点或强制关闭。完成可独立进行的文件审查；无法完成 notebook 显示核对时，明确标注“已写入、实际 notebook 渲染待检查”，不能报告已全部验收。
- 文件、内容、实际显示检查均完成后，报告 notebook 路径、处理章节及配对数量、中文可编辑性和验证范围。当前存在漏页、待核对内容或显示问题时据实说明。

## 7. 同周离线 HTML 阅读版

- 从**已完成并核对的同周 Notebook**生成 HTML，不单独重写译文；默认与 Notebook 放在同一 Week 目录，引用同一批实体原页图片。既有其他位置的用户文件不因采用新默认而擅自移动或删除。
- 沿用已确认的左侧目录、右侧逐页“英文原图 → 中文文字”布局，提供页标题／中文内容搜索；单页原图和译文的来源顺序、页码与 Notebook 一致。可复用主 SKILL 的 `scripts/build_course_reader.py`，按当前周的实际 Notebook 调整输入输出。
- HTML 是离线阅读副本，文字应可选择、复制和搜索；不得把译文烘焙成图片。生成后检查页数、图片路径、首末页和代表性的表格／代码／公式显示，并实际打开检查目录跳转和搜索。Notebook 改动后同步重新生成与复验 HTML，避免两版内容分叉。

## 8. Tutorial 原件与讲解合集

Tutorial 属课前预习，其翻译、讲解与解答归 03，不归 04。

- 教师 Tutorial 原件（题目 PDF/PPT、Tutorial Notebook、教师 Answers、配套代码与数据）的正本留在 01 对应周的 `Tutorial/` 子目录。03 默认在对应周目录下为每个 Tutorial 建单元 `WeekNN/Tutorial原件与讲解_<主题>/`（按章节授课的课程，章节与周的对应确认后同样按周放）。单元内放原件的逐字节副本并与讲解配对，让用户打开一个文件夹即可预习。03 根目录放一份 `00_Tutorial原件与讲解_索引.md`，按周列出各单元的原件副本、讲解入口，以及平台上没有 Tutorial 的周。这是“单一实体归属”的明确例外，仅限 Tutorial 原件；主讲义课件不复制。
- 副本不改写、保留原文件名；建立或更新时用 SHA-256 与 01 正本核对。教师更新原件时先替换 01 正本，再同步 03 副本并复核；两者不一致时以 01 为准并标明。不得用快捷方式或符号链接代替副本。
- 讲解形态按原件选择：幻灯片式 Tutorial 用第 1–7 节的逐页原图＋中文翻译；Notebook 式 Tutorial 用逐题／逐段讲解，写条件、解法、执行输出和解释，运行结果来自实际执行或明确标为推导。讲解只覆盖部分原件时（例如只讲了 Briefing PDF、练习 Notebook 暂无讲解），在索引和单元说明里写明。
- 教师标为 `without_solution` 或未附答案的练习默认只翻译题目要求；用户明确要求解题时另建解答文件，标明“非教师答案”。有教师 Answers 时，讲解引用其单元格并区分教师答案与本地解释。
- 先核对原件内课程代码、标题与教师清单；与所在课程不一致时标来源待核对，不当作本课官方 Tutorial。只有原件或只有讲解时不得报单元完整。
- 旧课程的 PDF 抽图／漏译脚本只是 PDF 流程候选，不能用来证明页图或翻译完整。

## 维护这一标准

新的周次沿用本流程，根据当前 PDF 调整页码映射和裁切。用户明确提出新的长期格式要求时更新此 Skill；单页特殊情况保留为该页处理记录。不要在每次笔记任务中重新安装工具、重建项目治理或改动其他课程内容。
