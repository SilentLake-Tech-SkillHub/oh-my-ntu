# 06c 考试信息汇报

读取[通用默认合同](../../references/defaults.md)与 [06 录播与课程信息](../【录播与课程信息】ntu-class-recordings/SKILL.md)；七段报告的字段、写法和数据格式见[汇报合同](references/report-contract.md)。本 Skill 只汇报"老师和平台实际说了什么"，不出模拟题（模拟卷归 07），不替代正式通知。

## 1. 先确定汇报对象

从用户这次的 Prompt、课程链接和本地课程目录确定：哪几门课、哪一次考试、考试日期、要检查的周范围。课程代码、周次名称一律按用户课程的实际情况写，不套用其他课程。

课程周与平台录播周的标签经常不同（例如平台按学期教学周命名，课程从第 1 周算起）。用录播上传日、录播封面或讲义标题、官方课表三者对齐后再动手，并在报告里写明对应关系。用户给的周范围之外，**考试前的最后一节课**往往会讲考试安排：一并检查，在报告中标为"补充"。

## 2. 刷新官方书面来源（只读）

按主 SKILL 识别学生平台后，逐项重新读取，不沿用旧记录：

- **公告**：必须加载到"共 N 条、已显示 N 条"。很多平台的列表默认只显示前 10 条，最早的"欢迎公告"常常写着考试日期。考试前几天老师常会新发"Quiz Arrangements"之类的公告，所以每次汇报前都要重读，并记录每条的发布时间。
- **课程内容页**：课程信息、考核说明、Quiz details / Quiz rules / 座位表、Sample Quiz、成绩册。Sample Quiz 只看概览页和用户本人已提交的作答记录，**不点"开始作答"**。
- **本地教师原件**：课程说明、第一份讲义或 Course Briefing 的考核页和日程表，包括图片里的表格。
- **截图**：每个书面来源截一张清晰图。会议链接、密码、他人姓名等内容要裁掉或打码后再用。

## 3. 取得录播文字稿

- **先找官方附件**：Kaltura / Media Gallery 录播页「Details」下拉菜单里有「Attachments」，常见为 `<编号> - <entryId> - PID <n>.txt`（原文）与同名 `.json`（逐词时间轴）。只看播放页、看不到附件，就断言"没有官方字幕"，是常见误判。
- **课程页内嵌的录播（跨域 iframe）**：把 iframe 的 `src` 在当前标签页顶层打开，进入 Kaltura 频道页。之后可以在同源下列出每条录播的附件（附件列表接口形如 `/attachments/index/index/entryid/<entryId>/entryView/1?format=ajax`）。
- **下载前确认**：先把清单列给用户（场次、文件名、来源、大小），得到确认再下载。批量下载一次确认即可。
- **下载方式**：在页面上下文 `fetch` 下载按钮指向的地址，同时算出 SHA-256，再把 base64 经已登录浏览器回传本地解码。签名令牌不进对话、不落盘。本地复核哈希后，按 06 的规则归档到 `WeekNN/` 并登记 ID、大小和哈希。
- **没有附件**时转 06b；附件和自动字幕都没有时，登记缺口，不自行转写冒充。
- **录制故障**：若老师改传往届录播，标为"往届录播"，其中的考试说法只作参考。

## 4. 检索考试信息

1. 用 `scripts/transcript_segments.py` 把逐词时间轴切成带时间戳的句子；没有 json 时可用 `.vtt`。
2. 用 `scripts/find_exam_mentions.py` 分三层检索：A 直接考试词（quiz、exam、MCQ、negative marking、calculator、seat、lab 等）；B 强调与排除（not tested、remember this、most important、memorize 等）；C 课堂小测标记（Wooclap、QR code、next question、closing in）。脚本按词边界匹配，避免 `exam` 命中 `example`；课程特有的词用 `--extra` 补充。
3. 每条命中都要读前后至少 4–8 句再下结论，排除老师拿"quiz 分数""考试"打比方的段落。识别自动转写错误（例如把 chapters 识别成 hatters），中文意思按上下文纠正，原文照录。
4. 课堂小测属于教师 Sample Quiz，每堂课一套，题目登记与答案依据按 [07 课堂小测样题](../【练习题与模拟考】ntu-practice-assessments/references/in-class-quiz-samples.md) 执行。课堂小测要同时找到出题时间和公布答案时间。答案只采用老师口述或投屏标出的 Correct answer；老师没公布的，标"本地判断"并写出依据。

## 5. 截取录播画面

用 `scripts/fetch_recording_frames.py` 按秒取帧。Kaltura 用缩略图接口的 `vid_sec` 参数，接口地址的前缀从频道页缩略图 URL 中取得。取帧前先识别录播版式：

| 版式 | 特征 | 处理 |
|---|---|---|
| `full` | 整帧就是投屏 | 取 1920 宽，缩到 1280 |
| `composite` | 左侧讲台摄像头，右侧投屏 | 取 1920 宽，只裁右侧投屏 |
| `camera` | 只拍到讲堂幕布 | 取 2560 宽，裁出右侧幕布 |

先用 `--contact-sheet` 生成缩略图总览，确认文字可读后再挑选。只放能传达信息的画面：老师口头讲、投屏却是无关内容的时间点，不放截图，只给原文。小测题取投票关闭、显示结果或答案之后的帧。

## 6. 组织七段报告

按[汇报合同](references/report-contract.md)写一份课程数据 JSON。每段的顺序都是：结论表 → 截图 → 原文对照（可折叠）。七段是：

1. 考试时间、地点、座位安排，附源文件链接和截图
2. 考试范围
3. 考试题型
4. 考试分数计算
5. 考试重点：Sample Quiz（平台 Sample 与每堂课的课堂小测，按课次分组）、Tutorial 的定位、老师强调的点、明确不考
6. 备考内容：按优先级列出，链接到本地 03/04/05/07 成品，并给考前清单
7. 原始内容对照：全部原文与来源登记

每条结论都标来源类型：官方书面、课堂口头、往届录播、本地判断、用户转述。书面与口头冲突时并列，写明采用哪条、为什么。官方没写的（例如座位表、各次 Quiz 的比例）明确写"未公布"，不推算。同一天有多场考试时，每门课各出一份，并在第 1 段注明同日其他考试的时间。

## 7. 生成、验证与汇报

- 课程数据 JSON 和取帧清单属于过程文件，放在课程目录与 SKILL 包之外的临时区。运行 `python3 scripts/build_exam_briefing.py DATA.json OUT.html` 生成单文件 HTML（图片内嵌，离线可开）。成品放 06 根目录，命名为 `YYYYMMDD_<课程代码>_<考试名>考试信息汇报_v<N>审阅版.html`。
- 链接一律相对 06 根目录。生成后检查以下几项：本地链接全部存在；图片数与数据一致；文件里没有签名令牌和会议密码；在浏览器实际打开，并把桌面宽度和 390px 手机宽度的截图放进对话。
- 回复用户时按同样的七段顺序汇报，先给结论，再说明新发现的官方更新、冲突和未公布项。同时同步 06 的来源状态文件，修正被新证据推翻的旧结论（例如"范围尚无书面公告"）。
