# 默认目录与命名合同

这些设置均可由用户当前 Prompt 覆盖。建立或整理既有课程前，核对当前实体、文件引用、版本状态和用户指定目录；仅有命名合同并不授权批量迁移、删除或重命名。获得授权迁移、改名或替换时，在课程目录外临时保存恢复所需字节并记录操作前后 SHA-256，再更新全部引用；成功切换后清理临时旧字节，只交付最新版，不建立历史版本库。Tutorial 副本同样用哈希与 01 正本核对。

```text
01_课程课件/
├── 00_课程说明/、00_课程案例/        （跨周材料，有才建）
└── WeekN_<主题>/
    └── 讲义/、视频/、Notebook/、Tutorial/  （按用途，有才建）
02_大作业/
【预习用】03_Notebook课件中英文对照解析/
04_复习笔记/
05_考前速记与关键术语宝典/
06_课堂录播字幕/
07_题库与模拟考试/
```

01 默认两级分类，根目录不平铺文件：一级按课次 `WeekN_<主题>/`（跨周材料放 `00_课程说明/`、`00_课程案例/`），二级按用途 `讲义/`、`视频/`、`Notebook/`、`Tutorial/`，只建有内容的目录；章节与周的对应须有官方日程、平台分组或用户确认，逐个文件核对内容后再归类，详见 01 子 SKILL。教师源文件名为 `WeekN_Weekday_主题.扩展名`；星期必须有课程表或正式来源，不猜，证据不足时保留教师原文件名。依赖原相对文件名的配套代码保留必要例外，不改写教师内容。

02–07 派生资料的文件名默认按 `[阅读顺序_]主题_用途[_套卷或必要范围]_载体.扩展名` 组织，具体生成见[整批交付合同](delivery-contract.md)。文件夹已经说明的课程和周次不机械重复；会脱离目录分享时补足必要上下文。阅读顺序号只有在有实际学习顺序时使用，不当成版本号。HTML写“阅读版／作答页”，Notebook写“可编辑笔记”等可辨识用途；代码讲解与课件中英对照要在名称前部区分。技术术语可以保留，但不使用 `ch6` 等内部代码代替主题。需要日期区分真实课次或通知时，将日期作为必要上下文保留；教师原件和运行依赖固定名不机械改写。

来源、日期依据、范围、修订号和审核状态在结构身份、页内说明／Notebook元数据及来源记录中保留，不要求全部堆进文件名。未经用户内容验收仅标审阅状态，不用final冒充定稿；Final确为考试正式名称时可保留。同一资料的不同载体共享名称主体与主题身份；总册由多份Notebook组成时明确记录聚合关系，不强制一对一配对。原件与派生件只有一个实体归属，Tutorial核对副本例外不变。

已有文件是否保留正文，与名称和目录是否符合本次要求分别判断。获授权的全目录整理须复核所有相关旧文件，不能只登记本次新建文件；仅改规则时不自动迁移课程实体。新增／修订按[整批交付合同](delivery-contract.md)记录更新前指纹、同步所有入口并清除被替代旧件。集合格式检查只证明所声明集合；全目录完成还须按[任务范围合同](task-delivery.md)对照用户指定范围逐项有处置和必要质量证据，不以文件数、无断链或部分集合通过替代。


全课程来源核对至少区分官方公告、课件和配套文件、录播字幕三类。每类建立官方清单与本地实体的对应关系；缺失、尚未发布、仅用户转述或本地推定都要明示。不要把目录存在、文件数量或自动检查等同内容验收。

课程目录默认只留教师原件、用户需要的成品及其离线显示或运行必需的资源。为制作成品临时生成的 Plan/流水目录、构建脚本、校验值清单、截图、缓存及导入用文件，不因制作过程而成为课程交付物；放在课程目录和 SKILL 包之外的临时工作区（如 `流程管理/执行计划/<计划名>/构建脚本/`）。用户内容验收前保留在临时区以便返工；用户验收后，核对成品不再依赖再清理。`.ics` 等导入文件仅在用户明确要求日历导入或保留文件时制作；仅作导入中间件的，在确认日历事件实际生效后清理本地中间件。不得因此删除教师原件、用户已有文件、Notebook 引用的原页图片或其他仍被成品依赖的资源；已有课程目录的清理仍按用户当次要求确定范围。

SKILL 包的 `scripts/` 只放被 SKILL 正文引用、不写死课程路径、课程代码或题目内容的通用工具；课程数据以参数或外部文件传入。课程专用构建脚本、题库数据与 `__pycache__` 等缓存不得进入 SKILL 包。每次改动 SKILL 包后，扫描 `scripts/` 中的绝对路径、课程代码与缓存目录，结果为 0 才算包结构校验通过。
